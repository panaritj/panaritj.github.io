Beauty Is All That Matters: Duck Typing and Protocols

July 17, 2026 · 2 min

The question arises: treat a thing based on what it does, or based on what it is?

Python was always clear on this. “If it quacks like a duck, treat it like a duck." You don’t ask an object for its pedigree, you ask it to quack.

This comes with a consequence: you don’t find out until you try. You usually don’t discover incompatibilities until some code actually tries to use the expected interface. And you rarely get to walk every path. It’s error-prone, slow, tiring, and worse than a mandatory two-hour synergy meeting. For big, important projects, “run it and see what explodes” is not a plan (done it with my life).

You’d like stronger guarantees before execution. A way to declare, up front: this is the behaviour I expect. We agree on a protocol. You implement the expected interface (at least on appearance, and appearance is all that matters) and we’re good to go.

Since Python 3.8, we have Protocols (PEP 544). No inheritance required. You don’t subclass anything; you simply conform. Then a type checker can verify that conformance before you ever run the program, so the “try it and see” moves from runtime to the editor. Protocols exist primarily for static type checking; by themselves they don’t change how Python executes your code.

from typing import Protocol

class Liar(Protocol):
    def lie(self) -> str: ...

class PrimeMinister:
    def lie(self) -> str:
        return "We will not raise taxes."

class PressSecretary:
    def lie(self) -> str:
        return "The President has full confidence in him."

def put_on_stage(x: Liar) -> None:
    print(x.lie())

put_on_stage(PrimeMinister())   # ✅
put_on_stage(PressSecretary())  # ✅ neither inherits Liar, both satisfy it

PrimeMinister and PressSecretary share no base class. They just lie the right way, and the type checker agrees before a single line runs.

If you also want this at runtime, decorate the protocol with @runtime_checkable and isinstance(x, Liar) starts working. One caveat: at runtime it only checks that the required members exist, not their signatures or types. The static checker is still the one reading the fine print.

Structural typing: conform, don’t inherit. Beauty really is all that matters.
